# Звіт до лабораторної роботи № 6

## 1. Тема, номер і варіант

- Предметна область: розклад занять
- Номер варіанта: 3 (незмінний у всьому Python-блоці)
- Операційна система: Arch Linux
- Версія Python: 3.14.7 (вимога проєкту — 3.11 або новіша)

## 2. Мета роботи

Створити Python-застосунок, який читає CSV, перетворює текстові поля на
типізовані значення, будує звіт за списками, словниками й множинами та
записує результат у текстовий файл. Код розділено на модулі, помилки
обробляються явно, а поведінку перевіряє pytest. Досягнуто: працює CLI,
`pytest` (45 тестів), `ruff` і збірка wheel проходять локально та в CI на
Ubuntu, Windows і macOS.

## 3. Формат CSV

Заголовок: `day,period,room,subject,teacher` (читання за назвами, порядок
стовпців не важливий).

| Поле | Тип | Правило |
|------|-----|---------|
| `subject` | `str` | непорожнє |
| `teacher` | `str` | непорожнє |
| `day` | `str` | непорожнє |
| `period` | `int` | більше 0 |
| `room` | `int` | більше 0 |

Вміст `data/input.csv`:

```
day,period,room,subject,teacher
Понеділок,1,101,Програмування,Олексів М. В.
Вівторок,1,215,Кросплатформні засоби,Рудик Ю. І.
Середа,1,98,Бази даних,Коваленко О. П.
```

Екранований рядок має такий вигляд (кома, лапки й переніс рядка в полі
беруться в лапки, лапки подвоюються):

```
Четвер,1,305,"Мережі, протоколи",Петренко В. Л.
Понеділок,2,110,"Математика ""вища""",Сидоренко Н. Г.
```

У вхідному файлі таких рядків немає, але розбір через `csv` і тест
`test_comma_quote_and_newline_in_text` їх покривають.

Правило порожнього входу: файл із заголовком без записів коректний (порожній
список, звіт із «немає даних»); повністю порожній файл без заголовка —
`DataError`.

Джерело даних: `data/input.csv` — експорт лабораторної № 5
(`java -jar lab01-1.3.0.jar --export ...`), три записи без змін. Змінено
лише рядок заголовка: українські назви стовпців (`день,пара,аудиторія,
предмет,викладач`) замінено на англомовні машинні назви, як вимагає
лабораторна № 6.

## 4. Структура модулів

| Модуль | Призначення |
|--------|-------------|
| `errors.py` | `DataError(ValueError)` — помилка формату або значення |
| `loader.py` | `csv.DictReader`, UTF-8, `newline=""`, перетворення типів, `LessonRecord` (`TypedDict`) |
| `analysis.py` | відбір за днем, лічильник за викладачем, множина аудиторій, межі пар, `summarize` |
| `reporting.py` | `format_report` (текст), `write_report` (запис через `with`) |
| `cli.py` | `argparse`, коди завершення, UTF-8 для stdout і stderr |

`loader.py` не друкує, `analysis.py` не відкриває файлів, `reporting.py` не
читає CSV. Код запуску стоїть під `if __name__ == "__main__":`, тож імпорт
модуля не запускає програму (перевіряє `test_import_does_not_run_cli`).

## 5. Перетворення даних

- **список:** `load_records` повертає `list[LessonRecord]` через comprehension
  над `enumerate(reader, 2)`; `filter_by_day` — comprehension з умовою;
- **словник:** `count_by_teacher` — dict comprehension з відсортованими ключами;
- **множина:** `unique_rooms` — set comprehension; у звіті аудиторії
  відсортовано;
- **типи полів:** `subject`, `teacher`, `day` — `str` (пробіли обрізано);
  `period`, `room` — `int`.

## 6. Функції

`summarize(records, *metrics, minimum_period=0, **labels)`:

- `*metrics` — кортеж назв числових полів (`period`, `room`);
- `minimum_period` — іменований параметр із типовим значенням `0`;
- `**labels` — словник підписів результатів за назвою метрики.

Приклад виклику:

```python
summarize(records, "period", "room", minimum_period=2, period="Пари")
# {"count": 1.0, "Пари": 2.0, "room": 20.0}
```

Невідома метрика — явна `ValueError`. Якщо всі записи відсіяно, визначені
метрики дорівнюють `0.0`.

## 7. Алгоритм аналізу

1. Відбір занять заданого дня (`--day`, за замовчуванням «Понеділок»), без
   урахування регістру й крайніх пробілів.
2. Агрегування: кількість занять за викладачем (словник), ключі відсортовано.
3. Унікальні значення: множина аудиторій.
4. Перша й остання пара відібраного дня: `min` і `max` номерів пар; для
   порожнього відбору — `None` («немає даних»).

Усе, крім загальної кількості записів, рахується для відібраного дня.
Порядок у звіті детермінований: викладачі й аудиторії відсортовано, формат
чисел фіксований.

## 8. Обробка помилок

`DataError` містить номер рядка (заголовок має номер 1) і назву поля;
першопричина зберігається через `raise ... from error`. Голого `except` немає;
CLI перехоплює лише `DataError` і `OSError`, а неочікувані помилки не
маскуються.

| Ситуація | Повідомлення | Код CLI |
|----------|--------------|---------|
| Хибне число | `Рядок 2: поле period має бути цілим числом` | 1 |
| Нуль або від'ємне | `Рядок N: поле room має бути більшим за 0` | 1 |
| Відсутній стовпець | `Відсутні стовпці: room` | 1 |
| Відсутнє або порожнє значення | `Рядок N: поле period відсутнє або порожнє` | 1 |
| Зайві значення в рядку | `Рядок N: забагато значень у рядку` | 1 |
| Порожній файл без заголовка | `Файл порожній: немає рядка заголовка` | 1 |
| Файл не в UTF-8 | `Файл ... не є коректним UTF-8` | 1 |
| Вихідний файл збігається з вхідним | `Вихідний файл не може збігатися з вхідним` | 1 |
| Файл відсутній або недоступний | `Помилка файлу: ...` | 3 |
| Хибні аргументи | повідомлення `argparse` | 2 |
| Успіх | — | 0 |

Повідомлення виводяться в stderr, а CLI явно задає UTF-8 для stdout і stderr.

  результат, незмінність входу, підсумок;

Позитивні випадки: коректні дані, успішний CLI. Крайові: порожній вхід, межа

## 15. Відповіді на контрольні питання

1. `pyproject.toml` описує пакет: назву, версію, залежності, команду запуску й
   налаштування інструментів (pytest, ruff).
2. Віртуальне середовище ізолює залежності проєкту від системного Python і
   відтворюється за `pyproject.toml`.
3. `newline=""` передає керування роздільниками рядків модулю `csv`, який сам
   коректно обробляє переноси рядків усередині полів.
4. `DictReader` повертає словники, де всі значення — рядки; відсутні значення
   в короткому рядку — `None`.
5. `split(",")` розірве поле з комою всередині лапок і не розрізнить перенос
   рядка в полі від кінця запису.
6. Список зберігає порядок і повтори; словник зіставляє ключ зі значенням;
   множина зберігає унікальні значення без гарантії порядку.
7. Comprehension зручний для одного прозорого відбору чи перетворення; для
   складної логіки, кількох умов чи побічних ефектів зрозуміліший цикл.
8. `*args` — кортеж позиційних аргументів, `**kwargs` — словник іменованих.
9. Змінний об'єкт створюється один раз і ділиться між викликами, тож стан
   «протікає» між ними.
10. `raise ... from error` записує першопричину в `__cause__`, тож вона не
    втрачається.
11. Так модулі легше тестувати окремо без файлової системи, змінювати та
    розуміти, а відповідальності не змішуються.
12. `with` гарантує закриття файла навіть тоді, коли під час роботи виникає
    виняток.
13. Щоб однакові дані завжди давали однаковий звіт, і його можна було
    перевірити тестом.
14. Файл лише із заголовком, файл без заголовка, відсутні стовпці й звіт для
    порожнього набору.
15. Тест поведінки перевіряє результат функції, а не назви внутрішніх змінних,
    тож переживає рефакторинг.
16. Файли `test_*.py` і `*_test.py` та функції `test_*`.
17. `ruff check` шукає типові помилки й порушення стилю, `ruff format --check`
    перевіряє форматування без змін файлів.
18. `0` — успіх, `1` — помилка даних, `3` — помилка файла, `2` — хибні
    аргументи.
19. Тести перевіряють поведінку, аналізатор — якість коду, пакетування —
    що пакет справді збирається й встановлюється; одне не замінює інше.
20. Вхідний CSV і його заголовок, правило порожнього входу, приклад звіту,
    команди запуску, коди завершення, результати pytest, ruff, wheel і CI.
